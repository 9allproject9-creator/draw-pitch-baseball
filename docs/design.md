# 그려던져! — 설계 문서

> 작업 이름: **그려던져!** (나중에 바꿔도 됨)
> 작성일: 2026-11-22

## 1. 무엇을, 왜

선을 한 붓에 아무렇게나 그리면(지그재그, 뱅글뱅글 루프 등) 공이 **그린 모양 그대로** 날아가는 야구 게임.
참고 영상(한붓마구왕)의 "말도 안 되는 궤적" 재미를 가져오되, 생김새·이름·화면은 우리만의 것으로 만든다.

- 목적: 친구들이랑 웃으면서 하는 게임. 이상한 공 던지고 상대가 당황하는 게 핵심 재미.
- 사용자 요구: AI 대전 + 친구 멀티(따로), 야구 룰로 번갈아 공격/수비하며 점수 경쟁, Render 배포, 모바일·PC 둘 다, **대충 만들지 말 것**.

### 목표
- 로비 → AI 대전 / 친구 대전(방 코드) 선택
- 진짜 야구 룰: 이닝 초/말, 스트라이크·볼·아웃, 주자, 득점
- 투구 = 선 그리기, 타격 = 날아오는 공을 타이밍 맞춰 터치/클릭
- 3D 경기장, 궤적 꼬리선, 타격 후 공이 필드로 날아가는 연출, 효과음
- 폰(세로/가로)·PC 모두 쾌적하게 동작
- Render 무료 플랜에 배포, 링크로 친구 초대

### 하지 않는 것 (이번 범위 밖)
- 3명 이상 한 방, 관전자, 랭킹/계정/로그인
- 도루, 번트, 수비 직접 조작, 선수 교체·로스터
- 채팅 입력 (대신 이모티콘 리액션만)

### 이러면 실패
- 그린 선과 실제 공 궤적이 다르게 보인다
- 멀티에서 두 사람 화면의 판정이 서로 다르다 (한 쪽은 삼진, 한 쪽은 안타)
- 폰에서 그리다가 화면이 스크롤/확대된다, 버튼이 너무 작다
- 이상한 선을 그릴 이유가 없다 (직구가 제일 좋으면 실패)

## 2. 만드는 방법 (Approaches)

| 방법 | 장단점 | 결정 |
|---|---|---|
| **A. Node.js + Socket.IO 서버 하나 (Render 웹 서비스) + Three.js 3D 클라이언트** | 서버 하나가 게임 화면 파일도 주고 멀티 방도 관리. Render에 그대로 올라감. 판정을 서버가 해서 두 화면이 어긋나지 않음 | **채택** |
| B. 브라우저끼리 직접 연결(WebRTC) | 서버 부담 적지만 연결 중개 서버가 어차피 필요하고, 학교·회사 와이파이에서 연결 실패가 잦음 | 제외 |
| C. 2D 캔버스로 단순하게 | 빠르지만 "이상한 궤적이 3D로 날아오는" 맛이 사라짐 | 제외 |

- 빌드 도구 없이 ES 모듈 + import map. Three.js는 npm으로 설치해 서버가 직접 서빙 (외부 CDN 의존 없음).
- 게임 규칙·궤적 계산·타격 판정은 `shared/` 폴더 하나에 두고 **서버와 브라우저가 같은 코드**를 씀.

## 3. 게임 규칙

- 기본 3이닝 (방장/AI 대전 시작 전에 1·3·5·9 선택)
- 원정팀이 초 공격, 홈팀이 말 공격. AI 대전에서는 내가 원정(먼저 공격) 또는 홈 선택 가능.
- 3스트라이크 삼진, 4볼 볼넷, 3아웃 공수교대
- 파울: 2스트라이크 전까지는 스트라이크, 이후엔 카운트 유지
- 마지막 이닝 말에 홈팀이 앞서면 그 즉시 끝 (끝내기 포함)
- 동점이면 연장, 최대 3이닝 추가 후에도 동점이면 무승부
- 주자 진루 (단순화):
  - 단타 +1루씩, 2루타 +2, 3루타 +3, 홈런 전원 득점
  - 볼넷: 밀어내기만 진루
  - 땅볼 아웃: 1루 주자 있고 2아웃 미만이면 40% 확률로 병살, 아니면 주자 1베이스씩 진루
  - 뜬공 아웃: 3루 주자 있고 2아웃 미만이면 희생플라이로 득점, 나머지 주자 그대로
- 확률은 서버의 시드 난수로 결정 (두 화면 동일)

## 4. 투구 — 선 그리기

- 투수 시점 카메라: 마운드 뒤 약간 위에서 홈플레이트를 봄
- 화면에 **투구 박스**(그릴 수 있는 네모)와 그 안의 **스트라이크 존** 표시
- 손가락/마우스를 누르는 순간부터 떼는 순간까지가 한 번의 투구 (떼면 바로 던짐 = 한 붓)
- **잉크 게이지**: 그릴 수 있는 선 길이에 한도가 있음 (무한 낙서 방지). 게이지가 다 차면 자동으로 던짐
- **투구 시간 제한** 15초. 넘기면 자동으로 볼

### 공이 선을 따라가는 방식 (핵심)
- 선의 각 점을 `시간`과 함께 기록 → 공이 그 타이밍 그대로 재생됨. **빨리 그은 부분은 빠르게, 천천히 그은 부분은 느리게** 날아감 (그린 그대로 던져짐)
- 공의 깊이(투수→홈)는 시간에 따라 진행, 화면상 위치는 그린 점과 정확히 일치하도록 3D 좌표를 역산 → 투수 시점에선 그린 선과 완벽히 겹침, 타자 시점에선 미친 3D 궤적으로 보임
- 전체 비행 시간은 그린 시간을 줄여서 0.55~2.8초로 맞춤 → 이걸로 구속(km/h) 표시
- 첫 순간엔 투수 손에서 출발해 그린 선으로 부드럽게 합류
- **선의 끝점**이 스트라이크 존 안이면 스트라이크 코스, 밖이면 볼 코스

### 이상하게 그릴 이유
- **변화 지수**: 총 회전량(루프 수), 꺾임(지그재그) 횟수, 길이로 계산
- 변화 지수가 높을수록 AI 타자의 컨택 확률이 떨어지고, 사람 타자는 눈으로 쫓기 어려움
- 대신 이상하게 그리면 시간이 걸려서 공이 느려짐 → **"빠르게 + 이상하게 + 존 안에 끝내기"** 가 실력
- 투구 후 궤적 모양에 따라 **구종 이름 자동 생성**: 직구, 커브, 슬라이더, 지그재그볼, 회오리볼 ×3, 8자 마구, 정신나간 마구 등

## 5. 타격 — 공 터치

- 타자 시점 카메라: 홈플레이트 뒤(포수 뒤 약간 위)에서 투수를 봄
- 공이 날아오며 꼬리선이 그려짐. 투수가 그린 선은 미리 안 보임
- **공이 타격 구역(홈플레이트 앞쪽)에 들어왔을 때 공을 터치/클릭** = 스윙
  - 위치 정확도: 터치 지점과 그 순간 공의 화면 위치 거리
  - 타이밍 정확도: 그 순간 공이 이상적인 타격 지점에 얼마나 가까운지
  - 둘을 합친 타격 품질로 결과 결정: 홈런 / 3루타 / 2루타 / 단타 / 파울 / 땅볼 / 뜬공 / 헛스윙
  - 빨리 치면 당겨치기, 늦게 치면 밀어치기 방향
- 안 치면: 끝점이 존 안 → 스트라이크, 밖 → 볼
- 타격 구역에 공이 없을 때 터치하면 헛스윙
- 타격 구역에 공이 들어올 때 홈플레이트 주변에 링이 반짝이는 보조 표시

## 6. AI

### AI 타자 (내가 던질 때)
- 난이도 쉬움/보통/어려움 (로비에서 선택)
- 존 안에 끝나는 공은 높은 확률로 스윙, 밖이면 낮은 확률로 헛손질 (변화 지수 높을수록 헛손질↑)
- 컨택 확률 = 난이도 기본값 × 구속 보정(느릴수록↑) × (1 − 변화 지수 보정)
- 컨택하면 품질 분포에 따라 결과

### AI 투수 (내가 칠 때)
- 직구·커브·지그재그·나선·8자·파도·낙서 등 템플릿을 무작위 조합해 선을 생성
- 난이도에 따라 구속·변화량·존 안에 넣는 비율이 달라짐
- 사람이 그린 것처럼 시간 정보도 생성

## 7. 멀티플레이 (친구 대전)

- 로비에서 닉네임 입력 → **방 만들기**(4글자 코드 + 공유 링크 `?room=ABCD`) 또는 **코드로 참가**
- 방장 = 홈팀, 참가자 = 원정팀. 방장이 이닝 수 선택 후 시작
- **판정은 서버가 함** (궤적·타격·주자·점수 전부). 브라우저는 보여주기만
- 흐름: 투수가 선 전송 → 서버 검증 후 두 사람에게 같은 궤적 + 시작 시각 전송 → 타자는 자기 화면 기준 시간으로 스윙 정보 전송 → 서버가 판정해 결과 전송 → 두 화면 같은 연출
  - 타자 스윙은 "공이 내 화면에서 출발한 뒤 몇 초"로 보내서 인터넷 지연에 불리하지 않게 함
- 수비 쪽 사람은 자기가 던진 공이 타자 시점에서 어떻게 날아가는지 보게 됨
- **이모티콘 리액션** (ㅋㅋ, 😱, 👏, 😡, 🔥) 서로 띄우기
- 끊김 처리: 60초 안에 같은 브라우저로 다시 들어오면 이어서 진행, 넘기면 남은 사람 기권승
- 경기 끝나면 **재대결** 버튼
- 서버 입력 검증: 점 개수·좌표 범위·시간·전송 빈도 제한

## 8. 화면·연출

- 로비: 게임 로고, 닉네임, [AI 대전] [친구 대전] 버튼, 설정(효과음, 이닝 수, 난이도)
- 경기 화면 HUD: 전광판(팀·이닝·점수), B-S-O 카운트, 주자 다이아몬드, 직전 투구 구속·구종 이름, 그리는 중엔 잉크 게이지·투구 시계
- 3D: 로우폴리 경기장(잔디·내야 흙·마운드·홈플레이트·파울라인·외야 펜스·관중석·조명), 우리만의 캐릭터 디자인(팀 색상 유니폼·모자), 투수 와인드업·타자 스윙·포수 포구 동작
- 타격 후 공이 필드로 날아가고 카메라가 따라감, 수비수가 공 쪽으로 달려감, 주자가 베이스를 돔
- 큰 글자 연출: "삼진!", "볼넷", "안타!", "홈런!!" + 홈런 때 폭죽
- 효과음은 파일 없이 브라우저에서 합성 (배트 소리, 미트 소리, 함성, 휘익)

## 9. 모바일 · PC

- 포인터 이벤트로 터치·마우스 같은 코드 처리
- 그리는 동안 스크롤·확대·당겨서 새로고침 막기
- 세로·가로 둘 다 지원, 화면 비율에 맞춰 카메라 시야 자동 조정
- 버튼 최소 44px, 폰에서 글자 잘 보이게
- 성능: 로우폴리, 그림자 최소화, 픽셀 밀도 최대 2배

## 10. 배포 (Render)

- GitHub 저장소 하나 → Render 웹 서비스 (무료 플랜, 싱가포르 리전 = 한국에서 제일 가까움)
- 빌드 `npm install`, 시작 `npm start`, 상태 확인 `/healthz`
- 무료 플랜은 15분 무접속 시 잠들고 첫 접속에 30초~1분 걸림 → 로비에 "서버 깨우는 중…" 표시
- 저장소 공개/비공개는 배포 직전에 사용자에게 확인

## 11. 테스트

- `shared/` 규칙 엔진 자동 테스트 (카운트, 아웃, 주자 진루, 이닝 종료, 끝내기, 연장, 궤적 역산, 타격 판정, AI 투구가 항상 유효한지)
- 서버 테스트: 소켓 클라이언트 2개로 방 생성→참가→투구→스윙→결과 흐름
- 브라우저에서 직접 플레이: PC 화면, 모바일 화면(세로/가로), 탭 2개로 멀티

## 12. 만드는 사람에게 맡기는 것 (내 판단으로 정한 부분)

- 게임 이름(그려던져!), 색상·캐릭터 생김새
- 수치 밸런스 (잉크 한도, 비행 시간 범위, 타격 판정 반경, AI 확률) — 직접 플레이하며 조정
- 구종 이름 목록
- 이닝 기본값 3, 연장 최대 3이닝, 병살 40%
